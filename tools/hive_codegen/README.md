# hive_codegen

Auto-generates PyHive's typed **core layer** from Hive's OpenAPI spec
(`api/core.yaml`) and keeps PyHive in sync on every Hive release — with no human
interaction unless a change is genuinely breaking.

## The split: generated core + curated ergonomics

PyHive is *not* a thin generated client. Its models carry an ergonomic layer
(injected `hive_client`, lazy relations, convenience methods, DRF-style filter
kwargs, custom dunders). So generation is split in two:

```
pyhive/src/types/
├── _generated/              ← regenerated every release, never hand-edited
│   ├── enums.py             ← every spec enum, PyHive-style str/IntEnum + __str__
│   ├── models.py            ← one Pydantic base class per real entity schema
│   └── manifest.json        ← machine record of schemas/fields/enums/endpoints
│                              (the drift-detection contract)
└── <resource>.py            ← curated: `class Exercise(_ExerciseBase): ...`
                               adds hive_client, lazy props, methods, overrides
```

When Hive adds a field or enum value, it flows into `_generated/` and is
inherited by the curated subclass automatically. The curated layer is only
touched when a change is genuinely breaking.

## Engine

The model layer is generated by
[datamodel-code-generator](https://github.com/koxudaxi/datamodel-code-generator)
(`--output-model-type pydantic_v2.BaseModel`, `--base-class HiveCoreItem`,
`--aliases`, `--strict-nullable`, `--collapse-root-models`). `models.py`
post-processes its output to PyHive conventions (relative enum import, plain
`datetime`/`str` types). Enums are emitted directly for exact member-name
fidelity (`ON_DONE`, `HANICH`, …). All behaviour is driven by
[`codegen.toml`](codegen.toml).

## Usage

```pwsh
# Regenerate + classify drift + update pyproject/README/version
python -m hive_codegen sync --spec ../Hive/api/core.yaml --repo-root .

# Dry-run: report drift only, write nothing
python -m hive_codegen sync --spec core.yaml --check

# In CI: emit GitHub outputs and a drift report, skip project-file edits
python -m hive_codegen sync --spec core.yaml --no-apply \
    --drift-out drift.md --github-output "$GITHUB_OUTPUT"
```

Exit code `0` = no breaking changes (safe to auto-merge); `2` = manual review
required.

## codegen.toml knobs

| Section | Purpose |
| --- | --- |
| `[aliases]` | spec wire name → PyHive python attribute (e.g. `parent_module` → `parent_module_id`) |
| `[spec.skip_fields]` | fields omitted from the base so the curated layer declares them (curated nested types) |
| `[spec.force_optional]` | spec-required fields PyHive treats as optional (`T \| None = None`) |
| `[spec.force_nullable]` | nullable but still required (`T \| None`, no default) |
| `[models]` | curated class → spec schema when names differ (`User` → `CourseUser`) |
| `[curated_only]` | models/enums kept hand-written (diverged from spec) |

## Drift policy

`drift.py` compares the new manifest against the committed one:

- **Additive** (new model/field/enum/member/endpoint/param) → safe, auto-merged.
- **Breaking** (removed or retyped field, removed model/enum/member/endpoint) →
  PR is labelled for manual review and not auto-merged.
